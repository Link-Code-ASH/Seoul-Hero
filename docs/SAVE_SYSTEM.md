# 저장 시스템

## 무엇을 저장하나요?

현재 버전은 `saveVersion: 11`입니다. `savedAt`은 저장한 시각이며, `meta`에는 협회 코인, 영구 진행, 해금과 통계, 주간 상태, 설정을 저장합니다. 전투 중인 적·투사체·HP 등 `RunState`는 저장하지 않습니다.

Google 로그인은 선택 사항입니다. 게스트는 기존 `seoul-gate.save`를 사용하고, 로그인 계정은 사용자 ID가 붙은 별도 브라우저 저장을 사용합니다. 영구 진행만 `seoul_gate_saves` 테이블에 저장하며 전투 중 상태와 한 판용 마력석은 올리지 않습니다. 테이블은 사용자 ID별 한 행이고, RLS가 자신의 행에 대한 읽기·추가·수정만 허용합니다.

첫 로그인 시 게스트 기록과 클라우드 기록이 모두 있으면 선택합니다. 선택하지 않은 쪽은 JSON 파일과 로컬 사본으로 보관합니다. 클라우드 저장은 읽었던 `revision`이 그대로일 때만 수정합니다. 다른 기기가 먼저 저장했다면 자동 병합이나 덮어쓰기를 하지 않고 선택 화면을 다시 보여줍니다. 네트워크가 끊기면 계정별 로컬 저장과 미전송 표시를 유지하고 연결이 돌아오면 재시도합니다. 로그아웃하면 계정별 기록은 보존한 채 게스트 기록으로 돌아갑니다.

`src/state/MetaState.ts`의 `createDefaultMeta()`가 기본값을 만듭니다. 기본 광화문 맵 `seoul`, 각성자 `awakener`와 마력탄 `manaBolt`는 처음부터 해금됩니다. 협회 상품의 가격과 효과는 `src/data/meta/index.ts`에서 변경합니다.

## 저장 흐름

화면을 연결하는 앱 계층이 `SaveManager`를 호출합니다. 게임 결과를 한 번 정산한 뒤, 코인샵 구매 뒤, 설정 변경 뒤에 저장합니다. 15초 주기와 탭 비활성화·페이지를 떠날 때도 현재 영구 진행을 저장합니다. 시작할 때 저장이 없으면 기본 저장을 만듭니다. 앱이 유지하는 `RunSettlement`가 같은 판을 한 번만 정산하여 중복 보상을 막습니다. 진행 중인 판은 정산하지 않습니다.

`SaveManager`는 `StorageAdapter` 인터페이스의 `getItem`, `setItem`, `removeItem`만 사용합니다. 브라우저의 실제 저장소는 `LocalStorageAdapter`가 연결합니다. 다른 실행 환경에서는 이 어댑터를 교체하며 전투/성장 코드를 바꾸지 않습니다. 브라우저 자체의 저장 제한·용량 부족·보안 오류는 게임을 중단시키지 않고 `status` 메시지와 실패 반환값으로 알립니다.

## 여러 창에서 열었을 때

각 창은 불러오거나 직접 저장한 마지막 원문을 기억합니다. 다음 저장 직전에 브라우저의 현재 원문과 비교하고, 다른 창에서 변경되거나 삭제됐다면 현재 저장과 사본을 건드리지 않고 자동 저장을 중지합니다. 오래 열린 창이 15초마다 예전 진행을 덮어쓰는 일을 막습니다. 이 경우 안내에 따라 해당 창의 현재 기록을 JSON으로 내보낸 뒤 새로고침하여 최신 기록을 불러오세요. 충돌 상태에서 가져오기도 저장 보호를 우회하지 않습니다. 명시적인 저장 초기화는 보호를 해제하고 기본 저장을 새로 만듭니다.

저장 형태와 버전은 바꾸지 않고 원문 문자열을 비교합니다. 이는 서로 다른 창의 오래된 상태를 감지하는 보호이며 여러 창의 진행을 합치는 기능이나 완전한 동시 쓰기 잠금은 아닙니다. 두 창이 극히 짧은 읽기·쓰기 사이에 정확히 동시에 저장하는 경우까지 원자적으로 잠그지는 않으므로 실제 플레이는 한 창에서 진행하세요.

## 원본과 복구 사본

- `seoul-gate.save`: 현재 저장.
- `seoul-gate.save.backup`: 직전의 정상 저장. 새 원본을 쓰기 전에 갱신합니다.
- `seoul-gate.save.recovery`: 파싱할 수 없는 원본을 가능한 경우 보관합니다.

주 저장이 손상되면 이전 정상 저장을 불러옵니다. 둘 다 사용할 수 없으면 기본 진행으로 실행하며 상태 메시지로 알립니다. 복구 사본은 마지막 자동 저장 시점보다 한 단계 이전일 수 있습니다. 브라우저 사이트 데이터 삭제나 비공개 모드는 이 자료를 지울 수 있으므로 장기 플레이에는 JSON 파일 백업을 권장합니다. 주소와 포트가 다르면 브라우저는 별도의 저장 공간으로 취급합니다.

## 검증과 미래 버전 보호

파일 버전과 최상위 구조를 확인하고, 잘못된 필드는 기본값 또는 안전한 범위로 복구합니다. 음수 마석, 과도한 강화 단계, 범위 밖 음량, 잘못된 boolean 값을 허용하지 않습니다. `__proto__`, `constructor`, `prototype` 등 위험한 객체 키는 제외합니다. 안전한 이름의 아직 모르는 콘텐츠 ID는 보존하여 일시적으로 콘텐츠가 빠져도 진행 기록이 사라지는 일을 줄입니다. 시작 캐릭터·무기와 이미 구매한 해금도 복원합니다.

현재 게임보다 높은 `saveVersion`은 구조를 추측하지 않습니다. 이전 호환 사본이나 기본 진행으로 화면은 열 수 있지만 자동 저장을 막아 원본을 보호합니다. 호환되는 새 게임 버전을 사용하거나 사용자가 명시적으로 저장을 초기화해야 보호가 풀립니다. 가져오기만으로 미래 버전 보호를 우회할 수 없습니다.

## 버전 변경 정책

저장 구조를 변경할 때는 다음을 함께 수정합니다.

1. `src/save/SaveData.ts`의 `SAVE_VERSION`을 1 증가시킵니다.
2. `src/save/migrations.ts`에 기존 버전 → 다음 버전 함수 하나를 추가합니다. 과거 이관 단계는 지우거나 새 의미로 바꾸지 않습니다.
3. `validation.ts`의 현재 구조 검증과 기본값을 갱신합니다.
4. 실제 이전 형태의 fixture로 이관 후 마석·구매·해금·설정이 유지되는 테스트를 추가합니다.
5. 이 문서에 변경 이유와 필드 의미를 기록합니다.

현재 v0 → v1은 개발용 레거시 예시로, `meta.coins`를 `meta.currency`로 옮깁니다. 이관은 한 버전씩 순서대로 실행하며 단계가 빠졌거나 잘못된 버전을 반환하면 안전한 복구 경로를 택합니다. 콘텐츠 수치만 바꾸고 저장 형태가 같다면 버전을 올릴 필요는 없습니다. 콘텐츠 ID는 저장의 연결점이므로 기존 ID를 바꿀 때도 명시적으로 이관해야 합니다.

## JSON 백업과 초기화

설정의 내보내기는 현재 영구 상태를 검증한 JSON 파일로 만듭니다. 가져오기는 JSON·버전·진행을 먼저 검증하고 브라우저에 실제로 저장한 뒤에 적용합니다. 잘못된 파일이나 저장 실패는 기존 메모리의 진행을 교체하지 않습니다. 초기화는 사용자가 확인한 경우에만 호출하며 원본·사본·손상 원본을 제거하고 새 기본 저장을 만듭니다.

`npm test`는 저장 재실행, 구매/설정 유지, 손상 복구, 저장 불가, 미래 버전 보호, 여러 창의 오래된 저장 차단·재로드·초기화, JSON 가져오기, v0 이관, 입력 검증을 확인합니다.

## v2 오디오 설정

`settings.muted`(boolean, 기본 false)를 추가했습니다. 기존 `masterVolume`, `musicVolume`, `soundVolume` 이름은 유지합니다. v1 → v2 이관은 기존 진행과 음량·개발자 설정을 보존하며 muted만 기본값으로 채웁니다. v0 저장은 v0 → v1 → v2 순서로 이관합니다. v2 백업은 이전 v1 게임에서 자동 덮어쓰지 않습니다.

## v3 Run/Meta 분리 (2단계)

v2 → v3에서 meta.unlockedItems(기본 빈 목록), meta.unlockedStages(기본 seoul)를 추가합니다. 기존 마석·영구 구매·해금·통계·음량·음소거·개발자 설정은 유지합니다. v0부터는 0 → 1 → 2 → 3을 순차 실행합니다.

저장 형태는 { saveVersion: 6, savedAt, meta }입니다. 검증은 허용한 Meta 필드만 복사하며 ownedWeapons, runItems, 상점 재고 및 최상위 run은 저장/가져오기에서 제외합니다. Stage 소비 재화는 0에서 시작하며 정산 때 실제 회수한 재화는 Meta 잔액에 더합니다. Wave 지갑과 미회수 픽업은 저장하지 않습니다. 현재 무기 레벨과 아이템은 Meta에 저장하지 않습니다.

각성 시스템은 제거했으며 기존에도 저장하지 않았으므로 각성 데이터용 migration은 없습니다. bestTime은 순수 전투시간으로 정산하며 예전 기록은 보존합니다. 이전 연속 생존 기록과 현재 Wave 기록은 구조가 다르므로 직접적인 성과 비교에는 한계가 있습니다.

## 3단계 스탯 변경
이번 통합 상점 개편은 Run 전용 상태만 바꾸므로 저장 버전은 v6을 유지하고 별도 migration을 추가하지 않습니다. 20개 스탯과 전투 문맥은 Run에만 있고 저장하지 않습니다.


## 9단계: Curse와 성과 보상
몬스터는 마력석 픽업을 드랍합니다. 획득하면 Run 재화가 증가하고 상점 지출은 Run 재화만 차감합니다. RunSettlement는 현재 지갑과 스테이지 성과 보너스를 종료 시 한 번 정산합니다. 결과 화면은 도달 Wave, 처치, 현재/전투평균 Curse, 현장 회수·Boss·Clear·Curse 보너스와 최종 마력석을 표시합니다.

Curse 위험 공식(src/data/enemyConfig.ts): HP/피해 배율=min(5,1+Curse×0.01), 속도=min(5,1+Curse×0.002), 스폰 빈도=min(5,1+Curse×0.005), 추가 FAST 엘리트 확률=min(0.25,Curse×0.001). 음수/비정상 값은 0 처리합니다. 적 생성 시 능력치를 적용하며 이미 생성된 적은 소급 변경하지 않습니다. 웨이브 최대 적 수 상한을 유지합니다.

보상(src/data/rewardConfig.ts): 기본=floor(진행 Wave 환산×8). 사망 시 완료 Wave+현재 Wave 전투 비율(최대1), Clear는 전체 Wave 수를 사용합니다. Boss 도달 +20, 처치 +40, Clear +100. 기본 서울20 Wave는 Curse0에서 총320마석. 전투평균 Curse 1당 총 보상 +1%, 최대 +100%. 전투 dt 동안 min(100,Curse)를 누적해 전투시간으로 나누므로 마지막 상점에서 Curse만 올리는 방식은 보상을 부풀리지 않습니다. 첫 Wave 즉시 종료처럼 실제 진행이 거의 없으면 반올림 내림으로 0마석일 수 있습니다. 처치 수는 통계로만 사용합니다.

코인샵은 HP, Damage, 이동 속도, Luck 훈련과 포탑·흡혈 회로·기능 허가를 판매합니다. 비용은 기본값×증가율^현재단계 올림이며 `data/meta`에서 관리합니다. 이미 해금한 상품은 다시 구매할 수 없습니다.

저장 v5: v4→v5에서 deferredMagicStone을 0으로 추가합니다. 기존 마력석·강화·설정·해금은 유지합니다. 버전0→1→2→3→4→5→6 순차 이관, validation/fallback/미래 버전 자동 덮어쓰기 금지/백업·복원·초기화를 유지합니다. Run 무기·아이템·Shop·Curse 누적은 저장하지 않습니다.

개발자 F3: Curse는 공통 스탯에서 curse와 가산값 지정. 마력석 추가, 선택 코인샵 상품 지급, 캐릭터/무기/아이템 ID 해금, 강제 Clear/Game Over, 보상 재계산 미리보기(재지급 없음). Save export/import/reset은 메인 설정의 기존 기능을 사용합니다.

## 10단계 확인
저장 v6: v5→v6에서 전투 효과음과 UI 효과음 볼륨을 분리했습니다. 기존 효과음 음량을 두 그룹의 초기값으로 안전하게 이관합니다. Master/BGM/Combat SFX/UI SFX/Mute 설정을 저장합니다. Run 아이템과 무기는 저장하지 않습니다.

## v7 게이트 진행과 주간 상태

v6→v7에서 `gateProgression`과 `weeklyGate`를 추가합니다. `gateProgression.highestUnlockedDepth`는 계정 공용 입장 가능 심도이며, `characters[characterId]`는 캐릭터별 최고 클리어와 보상 정산 완료 심도를 저장합니다. 상위 심도 클리어는 그 캐릭터의 미수령 하위 보상을 연속 구간으로 정산합니다.

`weeklyGate`는 KST 주차 키, 현재 복합 규칙 ID, 아직 나오지 않은 규칙 ID만 저장합니다. 같은 주에 재실행하거나 백업을 불러와도 다시 추첨하지 않습니다. 주간 규칙의 패널티와 베네핏은 데이터 한 항목에서 함께 적용됩니다. 조각형 단군의 축복 해금·조각·성장 단계는 `blessings`에 별도로 저장합니다.

## v8 협회 코인과 도전 기록

v7→v8에서 `associationCoins`를 추가해 현장 마력석과 게이트 성과 보상을 분리했습니다. 캐릭터별 심도 진행에는 `bestWaveByDepth`를 저장하여 미클리어 심도의 최고 도달 Wave를 대기실에 표시합니다. 최초 클리어와 실패 진행 보상은 협회 코인으로 정산되며 현장 마력석 잔액에는 섞이지 않습니다. 메인 메뉴의 코인샵은 `associationCoins`만 사용하고 구매한 기초 훈련과 콘텐츠 허가는 기존 `upgrades` 및 해금 목록에 저장합니다.

## v9 메타게임 책임 분리

v8→v9에서 MetaState를 `account`, `gateProgression`, `characters`, `sharedWeapons`, `blessings`, `wallet`, `association`, `weeklyGate`, `supply`, `offlineReward`, `statistics`, `settings`로 분리했습니다. 협회 코인·구매 단계·해금·심도·주간 상태·설정·통계는 새 위치로 보존합니다. 레거시 영구 마력석 `currency`와 `deferredMagicStone`은 환산하지 않고 제거합니다.

캐릭터·무기·축복 조각은 각 콘텐츠 ID의 진행 레코드 한 곳에서만 관리합니다. 보급 상자와 오프라인 보상은 이번 버전에서 저장 골격만 가지며 실제 지급은 하지 않습니다. RunState의 현장 마력석·무기·아이템·Wave 지갑은 계속 저장하지 않습니다. 맵은 `account.unlockedMapIds`, 심도는 맵과 무관한 `gateProgression.highestUnlockedDepth`에서 관리합니다.

# Save v10

v10은 오프라인 미수령 보상을 협회 코인, 보급권, 캐릭터 조각, 공용 무기 조각, 단군의 축복 조각으로 분리해 저장한다. v9의 계정 진행, 주간 상태, 재화, 성장 단계와 상자 기록은 그대로 이관한다. 상자 개봉 결과는 즉시 저장하며 연출 상태와 성장실 선택 탭은 저장하지 않는다.

# Save v11

v11은 주간 후보 축복과 선택값을 제거하고 `weekKey / ruleId / remainingRuleIds`만 저장한다. v10의 기존 축복 7종 진행과 미수령 조각은 새 조각형 축복 7종에 일대일로 이관한다. 다른 재화·게이트 진행·설정은 그대로 보존한다.
