## 후속 변경의 기준

### 게임과 기존 대시보드의 주소 분리

게임 개발 서버는 `127.0.0.1:5174`, 미리보기는 `127.0.0.1:4174`를 사용합니다. 기존 대시보드의 5173은 유지합니다. npm 명령뿐 아니라 사용자가 익숙한 `vite.cmd --host 127.0.0.1` 명령에도 적용되도록 `vite.config.ts`에 기본값을 모읍니다. `strictPort`로 예상 밖의 주소 변경을 막으며 이전 게임 저장은 JSON 내보내기/가져오기로 옮깁니다.

새로운 적 행동이나 무기 형태가 필요할 때만 행동 처리기를 확장합니다. 새 테마·다중 스테이지 선택·무기 진화·고유 능력은 실제 콘텐츠와 함께 만들며 현재 구조를 통째로 교체하지 않습니다. 오디오 재생은 두 번째 버전에서 아래 구조로 연결했습니다.

모바일의 주요 확인 대상은 가로 화면에서 조작 영역과 전투 가독성, 고밀도 구간의 실제 기기 성능입니다. 지금 있는 조이스틱만으로 모바일 대응이 끝났다고 판단하지 않습니다. 실제 측정으로 문제가 드러난 부분부터 개선합니다.

초기 API 확인 자료: [PixiJS Application](https://pixijs.com/8.x/guides/components/application), [Vite 시작 안내](https://vite.dev/guide/). 설치 버전의 실제 타입 정의와 실행 결과를 최종 기준으로 확인했습니다.

## 2026-09-07 이미지와 오디오

기존 Simulation/충돌/청크/저장 어댑터를 유지하고 출력 계층만 확장했습니다. 공용 PNG Texture를 재사용하는 ImageAssets와 기존 Sprite 풀을 연결했습니다. 에셋 누락 시 이전 도형을 비상 표시로 남깁니다. 청크 장식 배치는 데이터로 분리했습니다.

Web Audio API는 별도 라이브러리 없이 음악·효과음 버스, 음량 조절, 동시 재생 제한을 제공하므로 선택했습니다. 합성한 소리를 실제 WAV로 보관하여 나중에 녹음 파일로 바꿔도 게임 로직을 바꾸지 않습니다. 이벤트 목록은 필요한 전투 사건에 한정하며 범용 이벤트 프레임워크를 도입하지 않습니다. 한 프레임의 중복 소리와 고배속 소리 폭주를 제한합니다.

저장 v2는 음소거만 추가하고 기존 음량 키를 유지하여 호환성을 높입니다. 이관 전 meta 구조 검증으로 손상된 배열이 정상 저장으로 바뀌는 회귀도 방지했습니다.

추가 요청한 좌우 걷기는 시트 1개를 수평 반전하여 양방향에 사용합니다. 프레임레이트나 KeyboardEvent가 아니라 실제 이동 거리를 기준으로 재생하므로 입력 교체·배속·이동속도 강화에도 같은 규칙을 유지합니다. 별도의 애니메이션 프레임워크나 이동 시스템 재작성은 하지 않았습니다. 생성된 시트의 불규칙한 여백은 데이터의 Texture 영역/기준점으로 처리했습니다.

경험치는 무기, 각성 결정은 판 능력치, 마석은 영구 진행으로 분리했습니다. 기존 저장 v2를 그대로 사용하고 각성은 저장하지 않습니다. 영구 보너스가 포함된 기준값을 복사해 합산하여 리셋이 영구 진행을 훼손하지 않게 했습니다.

유효한 무기 후보가 3개 미만이면 실제 후보만 표시하고 모두 최대 단계이면 계속하기를 표시합니다. 3개를 채우기 위해 능력치나 회복을 다시 넣지 않습니다. 희귀 드랍은 별도 작은 배열과 누적 charges로 상한을 지키며 보상을 보존합니다. 범용 loot table이나 별도 상점을 도입하지 않았습니다.


## 4단계: 적 행동과 자원 분리
기존 순수 Simulation/스탯/무기/상태/저장은 유지했습니다. 적 ID 분기 대신 행동 처리기, 작은 공장 함수와 적 공격 모듈을 추가했습니다. 돈은 항상 드랍하고 경험치는 12%로 분리했습니다. 픽업 합산과 30초 돈 자동 회수는 가치 손실과 장기 누적을 줄이기 위한 선택입니다. 보스 사망 시 남은 드랍은 회수하되 결과 뒤 성장 화면은 열지 않습니다. 보상 목표는 무적 자동 플레이 3개 seed 기준이며 최종 인간 플레이 밸런스가 아닙니다. 저장 대상 Meta 구조는 바뀌지 않아 v3 및 기존 migration을 유지합니다. 신규 아트 대신 기존 이미지와 도형을 재사용했습니다.

## 5단계
기존 마력탄을 기본 각성자 고유 무기로 지정해 무기/이미지/저장 ID를 유지했다. 캐릭터 signatureWeaponId와 무기 signatureOwnerId를 검증하고 후보 필터에서도 소유 제한을 검사한다. 6슬롯과 vuck만 기존 보상 처리기에 확장했다. 실제 후보가 부족하면 기본 3개보다 제외 규칙을 우선하며 능력치나 중복 카드를 만들지 않는다. Meta 형태는 바뀌지 않아 저장 v3 유지.

## 6단계: 분기와 시차 공격
무기 보상 phase 안의 분기 대기 ID로 흐름을 확장했습니다. 분기는 공통 성장 이후 덮어쓰는 데이터로 관리하고 보상 처리기에 무기 ID 분기를 만들지 않았습니다. 연속 검격/폭격은 공통 예약 공격으로 처리하며 위치 고정, 수량 상한, Wave 정리 취소, 한 시전 흡혈 예산 공유를 적용했습니다. 실제 보유 무기와 분기는 Run 전용이라 저장 v3 유지.

회전 단검이 항상 공격하도록 수정한 뒤 보상 회귀 기준을 넘는 seed가 있어 경험치 pervevel을 9→9.5로 소폭 조정했습니다. 18~22회 목표는 유지합니다.

## 7단계 설치물
기존 Weapon/Reward/능력 계산 경로를 재사용하고 고정 개체만 StructureSystem으로 분리했다. 포탑/마력장 설치 주기와 발사/tick 주기를 분리해 공격속도가 중복 적용되지 않는다. 최대 48개로 제한하여 별도 ECS/풀 없이도 객체 수가 유한하다. 탄은 기존 풀을 재사용한다. 설치물은 Run 전용이므로 save v3 변경 없음.

## 8단계
상점 상태는 RunState 안에 두고 Meta 저장에 추가하지 않았다. 등급 내 아이템 수가 등급 확률을 바꾸지 않게 정규화한다. 상품 가격 고정, 방문별 리롤 횟수만 가격에 반영한다. 조건부 전투 이벤트 효과는 무리하게 전부 만들지 않고 현재 태그/설치물/흡혈 효과만 적용했다.

## 9단계 판단
마석은 적별 합산을 중단하고 별도 StageReward 계산으로 정산한다. 보상 스냅샷을 결과에 보관하고 WeakSet으로 재지급을 막는다. Curse는 전투 가중 평균으로 보상에 반영한다. v4는 기존 포탑 접근권을 유지하며 새 통계만 추가한다. 순찰 각성자는 기존 이미지/공격 행동을 재사용하는 최소 해금 예시다.

## 10단계: 현재 표현과 검증
기존 AI 이미지와 걷기 프레임을 보존하고 추가 적은 캐시된 실루엣으로 구별한다. 소리는 외부 저작물 없이 재현 가능한 WAV 합성 스크립트로 추가했다. 모바일 조작은 기존 InputManager에 연결한 Pointer 입력을 사용한다. 상점은 작은 가로 화면에서 스크롤하며 2열을 유지한다. 저장 구조 변경이 없어 v4를 유지한다. 이전 단계의 미구현 설명은 당시 판단 기록이며 현재 상태는 IMPvEMENTATION_STATUS.md를 따른다.
