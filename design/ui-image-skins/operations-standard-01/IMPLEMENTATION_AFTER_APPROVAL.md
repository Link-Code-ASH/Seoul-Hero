# 외관 승인 후 런타임 연결 계획

2026-10-05 **“좋아 좋아 적용해”** 승인 후 아래 연결을 실행했다. 승인된 PNG와 공용 헤더·정보판·목록·버튼·탭·팝업을 운영 화면에 적용했다. 실제 캡처와 확인 범위는 [runtime/QA.md](runtime/QA.md)에 기록한다. 아래는 승인 시 연결 범위의 원문이다.

## 1. 승인 소재와 데이터

승인 후 구조 1254×1254·조작 1448×1086의 생성 원본 두 시트, 추출 원본, 역할별 표시용 PNG 마스터를 프롬프트·출처와 함께 보존하고 실제 이미지 manifest와 기존 exporter의 복사 경로에 연결한다. 표시용 마스터는 생성된 모서리·테두리를 보존한 래스터 9분할 확장본이며 새로운 4K 모델 생성 원화로 기록하지 않는다. `godot/data/visuals/ui_materials.json`에 `ops/header`, `ops/info`, `ops/row`, `ops/popup`, `ops/primary`, `ops/secondary`, `ops/tab`, `ops/icon`의 원본 영역·9분할·논리 크기·배율·안전 여백을 기록한다. 임의의 기본 영역이나 crop 추정으로 연결하지 않는다.

이 변경은 시각 소재 데이터이며 공용 콘텐츠·비용·생산·시간·저장 구조를 바꾸지 않는다. 기존 승인 소재와 원본 출처를 삭제하지 않는다.

## 2. 공통 표시 책임

`HeroImageSkin`의 표면·상태 처리에서 같은 기본 PNG 기하와 글자 영역을 유지한다. 기본/선택/잠금/누름/비활성/위험 상태 및 `safe_padding` 기준을 공용 역할에 맞춘다. `HeroUI`는 네이티브 배치·입력·텍스트 책임을 유지하고 실제 운영 화면에 남은 구형 프레임 호출만 필요한 범위에서 승인 PNG 경로로 옮긴다.

화면별로 같은 기능이 `buttons`, `controls`, 상점 소재, 직접 tint를 섞어 사용하지 않도록 공통 역할을 선택한다. 전투의 값 갱신·입력·진행과 각 화면의 게임 행동은 기존 소유 모듈에 둔다.

## 3. 대표 화면에서 전체 운영 화면으로 연결

먼저 승인한 여섯 화면을 연결하고, 같은 역할을 사용하는 성장·협회·설정·상세·일시정지·결과·생환·조합 팝업·회수/보급의 일반 조작에 적용한다. 새로운 배치나 원화가 필요한 화면은 해당 시안을 별도로 제시한다.

- 길드: 공통 헤더·정보 패널·직원/작업 행·탭·버튼. 건물과 고정 관리 공간·직원 표시·패널 개폐·스크롤을 유지한다. `cstore/next`로 선택 탭을 표시하는 경로와 일반 행동의 상점 소재 사용을 제거한다.
- 로비: 공통 제목과 일반 도구 역할을 맞추고 `spy/deploy` 전용 단말을 유지한다. 선택 준비 진입은 `출동 준비`다.
- 게이트24: 이름·냉장 진열대·상품 카드·노란 구매면·잠금·가격을 유지한다. `cstore/*`는 이 상점에서만 사용한다.
- 각성자 선택: 기존 카드 기하·원화·유리·선택 테두리를 유지하고 헤더·상세·준비/최종 행동의 역할을 맞춘다. 최종 행동은 `작전 투입`이다.
- 자료집: 책등과 `codex/panel`을 유지하고 공통 헤더·탭·목록·상세 행동을 맞춘다.
- HUD: 기존 밀도·HP바·아이콘·값 갱신·일시정지 접근을 유지하며 공용 색·글자 역할을 반영한다.

성장 선택 행은 기본 목록 프레임을 유지하고 선택 표시만 적용한다. 일반 팝업과 조합 팝업의 내부 버튼·스크롤도 같은 공통 경로로 맞춘다. `support/panel`은 회수·보급 장면에만 남기며 해당 장면 원화와 보상 표시 연출을 유지한다.

## 4. 좁은 확인과 전달

필요한 PNG 가져오기·스크립트 오류와 필수 파일 누락만 확인한다. 승인 시안과 실제 연결의 915×412 배치·글자·안전 여백·상태 차이는 사용자 저장과 지급을 차단한 확인 도구로 비교한다. 실기기·청음·수동 플레이·전체 회귀와 전체 테스트는 별도 요청이 없는 한 기본 절차로 추가하지 않는다.

기능 버튼을 연결할 때 기존 명령·비용·구매·리롤·잠금·분기·보상·저장 경계를 유지한다. 사용자 저장을 복사·초기화하지 않는다. 완료 보고에는 연결한 화면·주요 파일과 실제 확인한 범위만 기록하고 외관 승인과 게임 QA를 혼동하지 않는다.
