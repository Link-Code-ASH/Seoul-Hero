# 서울 히어로 미래 아트 라이브러리

`index.html`을 브라우저로 열면 서버 없이 제작안과 생성 원화를 찾고 선택할 수 있습니다. 신규 원화는 게임에 연결하지 않은 후보입니다. 기존 승인 참고 이미지는 신규 디자인 수량에 포함하지 않습니다.

**2026-10-08 제작 완료:** 독립 원본 1,000종, 연속 프레임 효과 48종·384장, 완성 연출 80개입니다. `metadata-check.json`에 수량·고유 원본 해시·경로·프레임 확인 오류 0건을 기록했습니다. `previews/recipe-gallery-check.json`은 80개 연출의 실제 재생 확인, `previews/selection-gallery-check.json`은 선택 JSON 내보내기·가져오기·개인 기록 보존 확인 결과입니다.

## 직접 고르기

이름·태그·분류·테마로 찾고 썸네일을 누르면 원본, 프롬프트, 참고 이미지와 권장 용도를 볼 수 있습니다. 밝은·어두운·체크무늬 배경과 실제 표시 크기를 바꾸어 비교하세요. 연출 레시피를 선택하면 재생·일시정지·처음부터·시간 이동·배속을 조절할 수 있습니다.

마음에 드는 소재는 **선택 후보에 넣기**로 모으고 **내 메모**에 사용처나 수정할 점을 적으세요. **선택 내보내기**는 후보·즐겨찾기·메모를 JSON 파일로 보존합니다. 다른 브라우저에서는 **선택 가져오기**로 이어 볼 수 있습니다. 이 선택은 개인 기록이며 게임 연결 승인과는 별개입니다.

## 목표와 집계

무기 120, 각성자 80, 몬스터 160, 축복 100, 직원 80, 맵 60, 이펙트 240, 시설 80, 미래 재화 80: 독립 디자인 1,000종입니다. 이펙트는 투명 PNG 192종과 8프레임 효과 48종으로 나눕니다. 80개 연출 레시피·프레임·썸네일·수정본은 원화 종수에 합산하지 않습니다. `complete` 상태만 제작 완료로 집계하며 게임 연결 승인과 구분합니다.

원본은 `originals/<category>/<id>/<revision>/`, 개별 출처 기록은 `records/`, 실제 생성 프롬프트는 `prompts/`, 승인 스타일 참고 사본은 `references/`에 보관합니다. 추가 제작 시 기록이 없는 새 제작안부터 생성하며, 기존 원본을 덮어쓰지 않습니다.

## 제작 도구

원화 생성과 수정을 위해 **내장 image_gen**을 사용합니다. CLI/API 이미지 생성이나 API 키는 사용하지 않습니다. 도구가 반환한 생성 이미지 경로를 사용하여 다음 순서로 저장합니다.

```powershell
node art-library/tools/request.mjs <asset-id>
node art-library/tools/ingest.mjs <asset-id> <generated-image-path>
node art-library/tools/assemble.mjs
```

`--reviewed`는 해당 원화의 실제 외형·투명도·프레임 정합성을 사람이 확인한 경우에만 ingest에 지정합니다. 자동 파일 검사는 미술 검토를 대신하지 않습니다. 현재 이미지 준비 도구는 Codex 번들 Node/Sharp 경로를 사용합니다. 갤러리 사용에는 Node가 필요하지 않습니다.

`request.mjs`는 저장된 개별 프롬프트로 내장 생성 도구에 전달할 요청을 준비합니다. `prepare-prompts.mjs`는 새 제작안의 초기 준비용이므로, 수정 프롬프트가 저장된 기존 항목 전체에 다시 실행하지 않습니다.

신규 원화는 스타일 참고를 확인한 뒤 개별 제작안과 그림체를 문장으로 지정합니다. 기존 피사체를 반복 복제하지 않도록 신규 생성에는 이미지 편집 입력을 넘기지 않습니다. 생성물의 배경제거나 잘림 수리는 로컬 원본을 먼저 확인한 뒤 `edit-request.mjs <id> background|framing`의 실제 편집 요청을 사용합니다. 소재의 역할에 맞춰 외형을 바꿀 때는 `redesign`을 사용하며 같은 ID의 새 버전으로 보존합니다. 입력 대상 해시와 수정 프롬프트도 보존합니다.

투명 픽셀에 남은 RGB 때문에 원본 뷰어에서 배경이 있는 것처럼 보일 수 있습니다. `node art-library/tools/alpha-preview.mjs <id>`는 원본을 바꾸지 않고 밝은 바탕에 실제 알파를 합성한 검토 미리보기를 만듭니다. 배경·잘림 판정은 이 합성본과 갤러리 배경 전환으로 확인합니다.

100종씩 10개 제작 묶음은 각 묶음마다 무기12·각성자8·몬스터16·축복10·직원8·맵6·효과24·시설8·재화8로 구성됩니다. 갤러리에서 `묶음01`처럼 검색할 수 있습니다. `contact-sheets/representative-18.png`는 6열×3행의 대표 원화 파생 미리보기이며, 각 칸의 이름·원본 ID는 옆 JSON에 기록합니다.

연속 프레임은 4열×2행 생성 원본 시트를 보존하고, 같은 크기의 개별 PNG 8장을 추출한 뒤 파생 스프라이트시트를 만듭니다. 연출 레시피는 원화 ID와 표시용 타임라인만 참조합니다. 좌표는 앵커 기준 픽셀, 회전은 도, 키프레임의 `t`는 레이어 시작 기준 초입니다. `displaySize`는 스케일 1일 때 가장 긴 변의 표시 크기이며 원본 해상도와 별개입니다. 시퀀스 레이어의 `frameCount`·`fps`·`frameLoop`가 프레임 재생을 지정하고, 레시피의 `loop`는 전체 타임라인 반복 여부입니다. 지급·강화 판정·피해·저장은 연출 데이터에 포함하지 않습니다.

`contextLayers`는 기존 강화 아이콘·보급 상자·뚜껑 PNG의 표시용 키프레임입니다. 개봉 시안의 몸체 흔들림과 뚜껑 들림·회전·퇴장도 레시피에 기록합니다. 이 참고 PNG들은 신규 디자인 수량에 합산하지 않습니다.

## 게임 연결 경계

재화 이름과 용도는 미래 기획 후보입니다. 현재 지갑·시설·보상·콘텐츠·밸런스를 바꾸지 않습니다. 갤러리 애니메이션은 독립 시안이며 실제 Godot 적용이나 성능 확인을 의미하지 않습니다. 선택한 원화의 게임 연결은 별도 시안 승인 후 기존 이미지 manifest와 exporter를 통해 진행합니다.

게임 자동 테스트·전체 빌드·실제 플레이 QA는 실행하지 않습니다. 확인 범위는 라이브러리의 수량·경로·해상도·투명도·프레임 누락과 독립 갤러리의 검색·선택·PNG 로드·연출 재생입니다. 전체 제작 후 `node art-library/tools/assemble.mjs`와 `node art-library/tools/verify-library.mjs`로 카탈로그를 갱신하고 `metadata-check.json`에 파일 확인 결과를 기록합니다.
